# مين الأطليسي

لعبة أسئلة عائلية للأندرويد على غرار Family Feud — مضيف واحد وفريقين
بيتصلوا محلياً عبر Nearby Connections، **بدون سيرفر وبدون إنترنت**.

آخر نسخة جاهزة للتركيب (اللعبة + الديمو):
**[صفحة الإصدارات](../../releases/latest)**.

## كيف بتشتغل

- **جهاز المضيف** (أفقي) بيعرض السؤال واللوح وبيحكم صح/غلط. هو مصدر
  الحقيقة الوحيد.
- **كل لاعب على جهازه**. الجهاز ما بيوصله نص السؤال ولا نصوص الأجوبة
  المخفية أصلاً — اللاعب بيسمع السؤال من المضيف.
- شاشة اللاعب هي الزر، ولونها هو كل الرسالة:

| اللون | يعني |
|---|---|
| وميض أبيض/أسود | دورك — اضغط |
| أزرق | ضغطت، والمضيف عم يسمعك |
| أخضر | جوابك صح |
| أحمر | جوابك غلط — وبيضل أحمر لحد ما يرجع دورك |

التطبيق كله بالوضع الأفقي (landscape)، والواجهة RTL بالكامل والأرقام
هندية عربية. كل شاشة مضبوطة تخلص بشاشة وحدة — ما في تمرير بأي مكان،
والمحتوى بيضل بعيد عن النتش وحواف الشاشة.

## قواعد اللعب (نفس البرنامج)

كل جولة بتمشي هيك:

1. **المواجهة** — كل لاعب إله **رقم** بفريقه لما ينضم (١، ٢، ٣...)،
   ورقم بيواجه نفس الرقم بالفريق التاني — وش لوش. الرقم اللي عليه الدور
   بس هو اللي شاشته بتصير زر، والباقين بيشوفوا اللوح المخفي بدون السؤال.
   الرقم بيزيد كل جولة. أول واحد يضغط بيجاوب:
   - جاب الجواب رقم ١ ← فريقه بياخد اللوح فوراً.
   - جاب جواب أقل ← لاعب المنصة التاني بياخد فرصة؛ الأعلى بياخد اللوح.
   - غلط ← الدور بينتقل للفريق التاني. غلطوا الاتنين ← الزر بيرجع يفتح.
2. **اللعب** — الفريق صاحب اللوح بيجاوب **لاعب ورا لاعب بالدور**: اللي
   جاوب (صح أو غلط) ما بيرجع دوره إلا لما يخلّصوا كل زمايله. كل غلط = X،
   وبثلاث X بتنفتح فرصة السرقة.
3. **السرقة** — لاعب المنصة من الفريق المقابل عنده محاولة وحدة: صحّت ←
   بياخد كل نقاط الجولة، غلطت ← النقاط بترجع للفريق الأول.
4. **النقاط** — نقاط الجولة (pot) بتتجمّع من كل جواب مكشوف، وبتتضرب
   بمضاعف الجولة (`1, 1, 2, 3`) وبتروح **لفريق واحد بس** بنهاية الجولة.


## مسار اللعبة

1. **المضيف** يضغط «استضافة لعبة» ← بتفتح **إعدادات المضيف**: اسم الغرفة،
   أسماء الفريقين (بكيبورد داخل التطبيق)، عدد الجولات ومضاعف كل جولة،
   ثواني الجواب، ثواني قرار «نلعب أو نمرّر»، وعدد الأخطاء اللي بتفتح
   السرقة. بعدها «كمّل للوبي».
2. **اللاعب** يضغط «انضمام كلاعب» ويكتب اسمه، وبعدها بتبيّن له **لستة
   الغرف** القريبة — بيختار غرفة المضيف اللي بدّه ياها. أول ما يفوت بيشوف
   الفريقين **بأسماء المضيف** وبيدوس على الفريق اللي بدّه — بيقدر يبدّل
   لحد ما تبلّش اللعبة.
3. المضيف يضغط «ابدأ اللعبة»، وبعدها كل شي بيمشي من لوح المضيف.
4. بنهاية اللعبة: زر «رجوع للوبي» بيبلّش لعبة جديدة نظيفة (لاعبين جداد،
   أسئلة جديدة، نقاط من الصفر).

الإعدادات من الشاشة الرئيسية فيها **استيراد بنك الأسئلة** وبس؛ باقي
إعدادات اللعبة عند المضيف.

## بنية المشروع

| الموديول | الشغلة | يعتمد على أندرويد؟ |
|---|---|---|
| `core-game` | محرك القواعد: المراحل، البزّ، الأخطاء، السرقة، النقاط، الجولة السريعة | لأ — كوتلن نقي |
| `core-network` | بروتوكول الرسائل وغلاف Nearby Connections | إي |
| `data-questions` | بنك الأسئلة (٥٠ سؤال) وقارئه | لأ — كوتلن نقي |
| `app` | واجهات Compose وViewModels والتنقّل | إي |

`core-game` مقصود يضل بدون أي `import android.*` حتى يضل قابل لاختبار
وحدة كامل بدون جهاز ولا محاكي.

## البناء

بتحتاج JDK 17 أو أحدث وAndroid SDK (platform 34, build-tools 34.0.0). حط مسار
الـ SDK بملف `local.properties`:

```properties
sdk.dir=/path/to/Android/sdk
```

```bash
./gradlew test            # اختبارات الوحدة لكل الموديولات
./gradlew assembleDebug   # ينتج app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleDemo    # نسخة الديمو — معرض الشاشات
./gradlew assembleRelease # نسخة الإصدار
```

## نسخة الديمو (معرض الشاشات)

للتجربة على الواجهات بدون ٥ أجهزة ولا شبكة:

```bash
./gradlew assembleDemo
adb install -r app/build/outputs/apk/demo/app-demo.apk
```

بتنركّب **جنب** اللعبة (معرّفها `com.feudparty.app.demo` واسمها «مين
الأطليسي — ديمو»)، وبتفتح على معرض بيعرض كل شاشة باللعبة بحالة مزيّفة —
لوح المضيف بمراحله، شاشات اللاعب بألوانها الأربعة، الإعدادات، اللوبي،
النتيجة، والنهاية. التنقّل بين الشاشات من السهمين اللي تحت.

الشاشات نفسها هي شاشات اللعبة الحقيقية (نفس الكود)، بس بدون منطق: الديمو
بيعرض الشكل، مش القواعد. كود الديمو كله بـ `app/src/demo/` وما بيدخل
بنسخة الإصدار.

## نسخة الإصدار (release)

```bash
./gradlew assembleRelease   # app/build/outputs/apk/release/app-release.apk
```

بدون مفتاح إصدار، الـ APK بينوقّع بمفتاح الـ debug حتى يضل قابل للتركيب
للتجربة — **مش صالح للنشر على المتجر**. للتوقيع بمفتاح حقيقي، ضيف
لـ `local.properties` (مش محفوظ بالريبو):

```properties
RELEASE_STORE_FILE=/path/to/keystore.jks
RELEASE_STORE_PASSWORD=...
RELEASE_KEY_ALIAS=...
RELEASE_KEY_PASSWORD=...
```

## النشر على GitHub

كل وسم (tag) بصيغة `v*` بيشغّل
[ورك‌فلو الإصدار](.github/workflows/release.yml): بيشغّل الاختبارات،
بيبني نسخة الإصدار ونسخة الديمو، وبينشرهن كـ Release مع الـ APK‌ين.

```bash
./gradlew test
git tag v0.2.0 -m "..."
git push origin v0.2.0
```

بتلاقي الملفات بعدها على [صفحة الإصدارات](../../releases). رقم النسخة
بينحدّث بـ `app/build.gradle.kts` (`versionCode` و`versionName`) قبل الوسم.

## التشغيل

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

ركّب التطبيق على جهاز المضيف وعلى جهاز كل لاعب: المضيف يختار «استضافة
لعبة»، وكل لاعب يختار «انضمام كلاعب» ويكتب اسمه — المضيف بيوزّعهم على
الفريقين بالتناوب. لازم البلوتوث والواي فاي يكونوا مفعّلين على الكل.

> **مهم:** Nearby Connections ما بينختبر بشكل موثوق على المحاكي. قبل أي
> نشر، نفّذ [قائمة الاختبار اليدوي](docs/manual-test-checklist.md) على
> أجهزة حقيقية.
